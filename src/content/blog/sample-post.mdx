## The Problem

When you have six independently deployed micro frontends sharing a single browser window, state management stops being a library choice and becomes an architecture decision.

## What We Tried

We evaluated several approaches — from a shared Redux store to event-based communication to a custom state bus built on top of Module Federation's shared scope.

## The Pattern That Emerged

The key insight was treating shared state as infrastructure, not application code. Each micro frontend owns its domain state completely. Cross-cutting state lives in a thin coordination layer that every app can subscribe to but none can directly mutate.

## What I'd Do Differently

Start with the coordination layer from day one instead of retrofitting it after three teams have already built their own state management patterns.
